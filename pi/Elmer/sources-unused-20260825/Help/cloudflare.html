Remote Access — Cloudflare Tunnel

 

Remote Access via Cloudflare TunnelCloudflare Tunnel provides secure remote access to RigPi and ELMER SDR from anywhere in the world — without opening ports in your router or configuring dynamic DNS. The connection is encrypted, authenticated, and routed through Cloudflare’s global network.

Advantages over port forwarding: No router configuration required. Works behind carrier-grade NAT. HTTPS by default. No dynamic DNS service needed. Free for personal use.

How Cloudflare Tunnel Works

A small daemon (cloudflared) runs on your Raspberry Pi and maintains an outbound connectiion to Cloudflare’s network. When you visit your tunnel URL from anywhere in the world, Cloudflare routes the request through this connection to RigPi — all without any inbound ports open on your router.

Prerequisites

•A free Cloudflare account (cloudflare.com)

•A domain name added to Cloudflare (can be any registrar; transfer DNS to Cloudflare is free)

•RigPi connected to the internet

Note: You can use a free domain from services like Freenom, or purchase a low-cost domain (.com, .net, .org) from any registrar and point its DNS to Cloudflare. The tunnel itself is free. After a trial period the one-time cost is $5.

Step-by-Step Setup

1Create a Cloudflare account

Go to cloudflare.com and sign up for a free account. Verify your email address.

2Add your domain to Cloudflare

1.In the Cloudflare dashboard, click Add a Site

2.Enter your domain name and select the Free plan

3.Cloudflare will scan your existing DNS records

4.Follow the instructions to update your domain’s nameservers to Cloudflare’s nameservers

5.Wait for DNS propagation (usually a few minutes to a few hours)

3Install cloudflared on RigPi

Connect to RigPi via SSH and run:

curl -L https://github.com/cloudflare/cloudflared/releases/latest/download/cloudflared-linux-arm64.deb -o cloudflared.deb

sudo dpkg -i cloudflared.deb

Verify installation:

cloudflared --version

4Authenticate cloudflared with your Cloudflare account

cloudflared tunnel login

This opens a browser window. Log in to Cloudflare and authorize the certificate. A credentials file is saved to ~/.cloudflared/cert.pem.

5Create the tunnel

cloudflared tunnel create rigpi

This creates a tunnel named rigpi and saves a credentials JSON file to ~/.cloudflared/. Note the tunnel ID shown in the output.

6Configure the tunnel

Create the configuration file:

sudo nano /etc/cloudflared/config.yml

Add the following content (replace with your tunnel ID and domain):

tunnel: YOUR-TUNNEL-ID

credentials-file: /root/.cloudflared/YOUR-TUNNEL-ID.json

 

ingress:

 - hostname: rigpi.yourdomain.com

   service: http://localhost:80

 - hostname: sdr.yourdomain.com

   service: http://localhost:8001

 - hostname: sdr8002.yourdomain.com

   service: http://localhost:8002

 - service: http_status:404

This routes rigpi.yourdomain.com to the RigPi web interface and sdr.yourdomain.com to ELMER SDR.

7Create DNS records in Cloudflare

Run this command for each hostname you configured:

cloudflared tunnel route dns rigpi rigpi.yourdomain.com

cloudflared tunnel route dns rigpi sdr.yourdomain.com

cloudflared tunnel route dns rigpi sdr8002.yourdomain.com

This creates CNAME records in your Cloudflare DNS pointing to the tunnel.

8Install cloudflared as a system service

sudo cloudflared service install

sudo systemctl enable cloudflared

sudo systemctl start cloudflared

The tunnel now starts automatically on boot.

9Test the connection

From any device on the internet, open your browser and navigate to https://sdr.yourdomain.com. ELMER SDR should load with a valid HTTPS certificate.

Verifying the Tunnel Status

Check the tunnel status at any time:

sudo systemctl status cloudflared

Or view the Cloudflare dashboard at dash.cloudflare.com — select your domain, then Zero Trust → Networks → Tunnels.

RigPi Cloudflare Settings

The RigPi System page shows the current Cloudflare Tunnel status and allows you to enable or disable the tunnel without SSH. Look for the Cloudflare Tunnel section in System → Settings.

HTTPS Benefits for ELMER

Accessing ELMER via HTTPS through Cloudflare Tunnel enables browser features that require a secure context:

•Clipboard API — The Copy / View button in the Workability Index can copy formatted HTML to the clipboard, which pastes with Courier New font into email clients

•Audio device enumeration — The browser can list and label available audio output devices

•Enhanced security — All traffic is encrypted between your browser and Cloudflare

Security Considerations

Important: Your RigPi will be accessible from the internet. Ensure all user passwords are set before enabling the tunnel. Use strong passwords, not the factory defaults.

Additional security options available in Cloudflare Zero Trust (free tier):

•Access policies — Require email authentication before accessing your tunnel URLs

•IP restrictions — Limit access to specific IP addresses or ranges

•One-time PIN — Require a PIN sent to your email for each login

To add authentication, go to Zero Trust → Access → Applications in the Cloudflare dashboard and create an application for your tunnel hostnames.

Troubleshooting

Problem

Solution

Tunnel shows offline in dashboard

Check sudo systemctl status cloudflared and review logs with sudo journalctl -u cloudflared

DNS not resolving

Allow up to 24 hours for DNS propagation; verify CNAME records in Cloudflare dashboard

502 Bad Gateway

The local service (RigPi or ELMER) is not running; check sudo systemctl status sdr_web@8001

Credentials file not found

Ensure the JSON credentials file path in config.yml matches the actual file in ~/.cloudflared/

Audio not working remotely

WebRTC audio works over HTTPS; verify you are accessing via the https:// tunnel URL
