# Ask Elmer voice compatibility

Ask Elmer accepts typed questions on every supported RigPi browser. On compatible
browsers it can also transcribe a spoken question, listen for the phrase “Hey
Elmer,” and read completed answers aloud.

## Requirements

- Open RigPi through a trusted HTTPS address. Browser speech recognition is not
  available from an ordinary `http://rigpi.local` page.
- Give the browser permission to use the device microphone.
- Keep the Ask Elmer page open, visible, and the device awake. “Hey Elmer” is a
  page-level listener, not an operating-system wake word.
- On Apple devices, enable Dictation and allow Safari under Privacy & Security >
  Speech Recognition when those settings are presented.

## Controls

- **Ask by voice** listens for one question and submits it.
- **Hey Elmer: On** listens for “Hey Elmer” followed by a question.
- **Read answers aloud** reads the substantive answer and stops before its
  References section.
- **Stop speaking** stops the current spoken response.
- **Check voice compatibility** tests HTTPS, microphone capture, recognition,
  playback, browser-tab mode, and page visibility. Its report can be copied for
  technical support.
- **Voice language** selects automatic question-language detection or a specific
  browser speech locale. Choices include English, French, Spanish, German,
  Swedish, Italian, Dutch, Portuguese, Japanese, Chinese, and Korean. The choice
  is remembered by that browser; it does not limit the languages Elmer can
  understand.
- **Hey Elmer** recognizes common wake phrases in those languages, including
  “Salut Elmer,” “Hola Elmer,” “Hallo Elmer,” and “Hej Elmer.”

## Multilingual questions

For a non-English question, Elmer preserves the original request and creates a
short structured plan. The plan translates the search meaning into English for
the RigPi knowledge base and identifies any permitted callbook or FCC lookup.
Elmer then answers in the original language. Callsigns, commands, menu names,
paths, model names, and settings remain unchanged.

This planning step may add a brief delay before a local lookup begins. Private
station data remains on the RigPi: the cloud returns a validated connector plan,
the RigPi performs the lookup, and only the limited result needed for the answer
is supplied to Elmer.

## Expected browser support

- Current Safari on macOS: voice input and playback over HTTPS.
- Current Chrome on Windows or macOS: voice input and playback over HTTPS.
- Current Edge on Windows or macOS: voice input and playback over HTTPS.
- Firefox: spoken playback is generally available; browser speech recognition
  may be unavailable, so use typed questions.
- Mobile Safari and Chrome on Android: voice support is device- and
  version-dependent and should be confirmed with the compatibility check.
- Browsers on iPhone and iPad and installed/home-screen web apps may impose
  additional recognition restrictions.

## Privacy and network use

Ask Elmer does not send microphone audio to rigpi.net. Speech recognition is
provided by the browser and may send audio to Apple, Google, Microsoft, or
another browser-operated speech service. The recognized text is submitted to
Ask Elmer as the user’s question. Elmer answers in the language of the question
unless the user requests another language. Spoken playback is generated by the
browser or operating system and does not consume OpenAI tokens.

## Limitations

Wake listening stops when the Ask Elmer page is hidden, the browser is
backgrounded, or a mobile device locks. A browser may also end a recognition
session after silence; Ask Elmer attempts to restart listening while wake mode
remains enabled. Browser transcription can substitute synonyms—for example,
“photo” and “photograph”—so live-data routing recognizes common variations.
