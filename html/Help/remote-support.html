Temporary Remote Support

Temporary Remote Support lets a trusted RigPi support technician diagnose a station without exposing SSH port 22 or asking the station owner to configure a router. Access uses an administrator-approved public key and a secure WebSocket connection.

Before you begin

•The RigPi must have a working Internet connection.

•You must be signed in to RigPi as an administrator.

•Obtain the technician's complete Ed25519 public key and independently verify its fingerprint.

A public key is safe to share. It normally begins with ssh-ed25519, followed by a long encoded value and an optional comment. Never ask for or accept the technician's private key.

Choose a connection

•Temporary address — no domain required is recommended for most support sessions. RigPi creates a random encrypted trycloudflare.com address automatically. The station owner does not need a Cloudflare account, domain name, connector token, DNS setting, or router port-forwarding rule.

•Existing secure station address uses the permanent HTTPS address configured under Native HTTPS (DuckDNS), or the saved Cloudflare Remote Access address when native HTTPS is unavailable. Choose this only when that connection is already working.

A temporary address exists only for the current support session and may be different the next time support is enabled. It is intended for temporary diagnostic access, not permanent RigPi remote operation.

Enable support access

1.Open Settings > Accounts > User Settings.

2.Find Remote Support Access.

3.Paste the entire Ed25519 public-key line. Copying only the long center portion is not sufficient.

4.Compare the displayed fingerprint with the fingerprint supplied by the technician.

5.Leave Temporary address — no domain required selected unless you want to use the station's existing secure DuckDNS or Cloudflare address.

6.Select an access period: 1, 4, 24, or 72 hours.

7.Select Enable Remote Support.

8.Wait for Remote support ready. Creating a temporary address normally takes several seconds.

9.Select Copy and send the displayed Support URL to the technician. Do not send passwords, API keys, DuckDNS or Cloudflare tokens, or any private key.

While access is enabled, RigPi runs a local support bridge and permits key-authenticated SSH inside the secure WebSocket connection. The temporary public address exposes only that bridge, not the RigPi login page or general web interface. The support key cannot use SSH agent forwarding, TCP port forwarding, or X11 forwarding.

End a support session

Select Revoke Now as soon as the session is complete. RigPi removes the managed support key and stops the support bridge and temporary address. If you do nothing, all three are disabled automatically when the selected period expires.

Access is powerful. An authorized support technician can inspect and change the RigPi operating system. Enable it only for someone you trust, for the shortest practical period, and remain available while work is being performed.

Security and recovery behavior

•Only the key shown in the Remote Support section is managed by this feature. Other SSH keys are not changed.

•The private key never resides on RigPi.

•Disabling or expiring access stops the remote support endpoint as well as removing the managed key.

•Restarting RigPi ends the support session and removes any stale temporary support key before SSH starts.

•Factory Reset removes the managed support key and disables Temporary Remote Support.

•A separate public key should be used for each support technician so access can be identified and revoked independently.

Troubleshooting

Message or symptom

What to check

Paste a valid Ed25519 SSH public key

Paste the complete line beginning with ssh-ed25519, not only its center field.

Public key already has permanent SSH access

Remove that key from the owner's permanent authorized_keys entries before using it for time-limited support. RigPi does not remove unrelated keys automatically.

Support address unavailable

Confirm that RigPi has Internet access. Select Revoke Now, then enable support again. For an existing station address, confirm that Native HTTPS or Cloudflare Remote Access is connected.

Technician cannot connect

Check that access has not expired, the displayed fingerprint matches, and the technician is using the displayed Support URL.
