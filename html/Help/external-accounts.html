External Accounts

RigPi SDR works with several optional third-party services that extend its capabilities. Each service requires a free or low-cost account. This page describes what each service does and how to set it up.

RigPi Elmer Service

The hosted RigPi Elmer Service provides Ask Elmer answers, Elmer Control command interpretation, and live-caption translation. A ChatGPT subscription, OpenAI account, and personal OpenAI API key are not required.

Connect this RigPi

1. Sign in to RigPi with an administrator account.

2. Open Settings > Accounts > User Settings and locate RigPi Elmer Service.

3. Click Configure, enter a name for the station, and have the displayed six-character code approved by the RigPi Elmer administrator. Approval may take up to 24 hours; you may leave the page and return later.

4. When Connected appears, use View Usage to see this station's allowance and aggregate activity.

Security: The protected station credential is stored locally and is never displayed in the browser. Disconnect revokes it immediately. After a Factory Reset, connect the RigPi again.

See Set Up Ask Elmer, Elmer Voice and Elmer Control for complete operating instructions, examples, privacy information, and troubleshooting.

HTTPS Remote Access

Choose one method. Native HTTPS with DuckDNS is the straightforward free choice when router port 443 can be forwarded. Choose Cloudflare Tunnel when port forwarding is unavailable, the Internet connection uses CGNAT, or concealing the station’s public IP address is preferred.

Native HTTPS with DuckDNS

Native HTTPS provides a permanent secure RigPi address using a free DuckDNS hostname and an automatically renewed Let’s Encrypt certificate. It supports browser microphone permission and remote RigPi operation without requiring a purchased domain or Cloudflare account. Unlike Cloudflare Tunnel, it requires router port forwarding and exposes the station’s public IP address.

1. Create a hostname at DuckDNS.

2. Sign in to RigPi as an administrator and open Settings > Accounts > User Settings.

3. Under Native HTTPS (DuckDNS), select Configure. Enter the DuckDNS name without .duckdns.org, a certificate email address, and the DuckDNS account token, then select Set Up. RigPi fills each blank SDR Remote field with that account’s numbered secure path, such as https://your-rigpi.duckdns.org/sdr1; existing custom or Cloudflare destinations are preserved.

4. In the router, forward external TCP port 443 to TCP port 443 at the RigPi’s reserved local address. Do not forward port 80. Disable or move router WAN administration if it is using port 443.

5. Test the displayed https:// address from a phone with Wi-Fi off. Some routers do not support using the public address from inside the same LAN.

Security: Use strong RigPi passwords before opening port 443. The DuckDNS token is stored in a root-only file and is never returned to the browser. If the token is recreated at DuckDNS, enter it in the Token field and select Update Token. Factory Reset removes the local token and certificate but does not delete the hostname from DuckDNS.

Optional memorable address: An existing HTTPS website or vanity domain can redirect visitors to the DuckDNS address without another certificate on RigPi. For example, https://radio.example.com/ can return an HTTPS redirect to https://your-rigpi.duckdns.org/. The browser address changes to DuckDNS after the redirect. Keeping the vanity hostname visible requires separate DNS and certificate configuration and is not part of normal RigPi setup.

Cloudflare Tunnel

Cloudflare Tunnel provides secure remote access to RigPi SDR from anywhere on the internet — without opening ports in your router or exposing your home IP address. Traffic is encrypted end-to-end through Cloudflare's global network.

RigPi SDR is pre-configured to publish two URLs through Cloudflare Tunnel:

sdr.rigpi.org — the main SDR panadapter and radio control interface

sdr8001.rigpi.org — direct access to SDR instance on port 8001

Why Use Cloudflare Tunnel?

No port forwarding required in your router

Your home IP address is never exposed

Works through carrier-grade NAT and IPv6-only connections

Free tier is sufficient for RigPi SDR use

Setting Up Cloudflare Tunnel

1.Create a free account at cloudflare.com.

2. Add a domain you own to the Cloudflare account. A permanent named station tunnel requires a domain; RigPi’s temporary Remote Support option can create a short-lived trycloudflare.com address without one.

3.In the Cloudflare dashboard, go to Zero Trust → Networks → Tunnels and click Create a tunnel.

4.Choose Cloudflared as the connector type and give the tunnel a name (e.g., rigpi).

5.Copy the tunnel token provided by Cloudflare.

6.On RigPi, install and configure the cloudflared connector using the token. Enter the following commands in an SSH terminal:

curl -L https://pkg.cloudflare.com/cloudflare-main.gpg | sudo tee /usr/share/keyrings/cloudflare-main.gpg >/dev/null

sudo apt install cloudflared

sudo cloudflared service install <your-token>

7.In the Cloudflare tunnel dashboard, add public hostnames pointing to http://localhost:80 for the main interface and http://localhost:8001 for the SDR instance.

8.Save the configuration. RigPi SDR is now accessible remotely via your Cloudflare hostname.

Note: Cloudflare’s tunnel service can use its free plan, but the permanent public hostname normally requires a domain owned by the station operator.

After either HTTPS remote-access method is working, an administrator can optionally enable time-limited diagnostic access for a trusted RigPi support technician. See Temporary Remote Support.

Pushover

Pushover delivers real-time push notifications from RigPi SDR to your iPhone, Android, or desktop. RigPi SDR uses Pushover to alert you to events such as new DX spots matching your filters, propagation changes, or system alerts.

Why Use Pushover?

Instant alerts on your phone when a wanted DX station is spotted

Works when you are away from the radio

One-time purchase of $5 per platform (iOS or Android); no subscription required

Setting Up Pushover

1.Create a free account at pushover.net.

2.Note your User Key shown on your Pushover dashboard after logging in.

3.Create an application in the Pushover dashboard: click Create an Application/API Token, give it a name (e.g., RigPi SDR), and save. Note the API Token.

4.Install the Pushover app on your iPhone or Android device. A 30-day free trial is included; after that, a one-time $5 purchase unlocks the app permanently.

5.In RigPi SDR Settings, enter your Pushover User Key and API Token in the Notifications section.

6.Use the Test button in RigPi SDR to confirm notifications are working.

Note: Your User Key and API Token are sensitive. Do not share them. They can be regenerated from the Pushover dashboard if compromised.

QRZ

QRZ is the world's largest amateur radio callsign database. RigPi SDR uses the QRZ XML API to look up callsign information including the operator's name, address, grid square, country, DXCC entity, LoTW status, and photo. This information appears in the ELMER Workability Index panel when you look up a DX station.

QRZ Account Levels

QRZ offers several account levels. The XML API used by RigPi SDR requires a QRZ XML Subscription:

Free account — callsign page access via browser only; XML API not included

QRZ XML Subscription — required for RigPi SDR integration; provides programmatic callsign lookup. Available at qrz.com/page/xml_data.html.

Note: Without a QRZ XML Subscription, callsign lookups in the ELMER Workability Index will return limited data. Grid square information used for path calculations may not be available.

Setting Up QRZ

1.Create or log in to your account at qrz.com.

2.Purchase a QRZ XML Subscription if you do not already have one.

3.In RigPi SDR Settings, enter your QRZ username and password in the QRZ section. RigPi SDR uses these credentials to obtain a session key from QRZ at lookup time; your password is stored locally on RigPi and is never transmitted to third parties.

4.Click any DX callsign in the ELMER Workability Index to test the lookup. The operator's name, location, grid square, and photo (if available) will appear in the QRZ panel.

Note: After a Factory Reset, QRZ credentials must be re-entered in Settings. See System Settings for more information.

Email Notifications

RigPi sends outgoing email through a standard SMTP account. Gmail, Outlook/Microsoft 365, Yahoo, a hosting-provider mailbox, and other SMTP services are supported. A Google API key and Gmail API project are not required.

Email is used for test and notification messages and for sending supported Elmer and Workability reports. The outgoing SMTP account is shared by this physical RigPi; the destination for a test message is the Email address near the top of the selected user account.

Configure outgoing email

1. Sign in to RigPi as an administrator and open Settings > Accounts > User Settings.

2. Enter the test-message destination in the account's Email field, then locate Email Notifications and select Configure.

3. Select Gmail, Outlook / Microsoft 365, Yahoo, or Custom SMTP. A preset fills the usual server, port, and encryption values; confirm them against your provider's current instructions.

4. For Custom SMTP, enter the SMTP server, port, and security type: STARTTLS, TLS/SSL, or None. Use an encrypted connection whenever the provider supports one.

5. Enter the SMTP username and password. The username is commonly the complete email address. Gmail and Yahoo generally require an app password rather than the normal webmail password. Other providers may require a mailbox-specific password or SMTP authorization.

6. Enter the From Email address and optional From Name. Many providers require From Email to match the authenticated mailbox.

7. Select Save, then Test. Confirm that the message reaches the Email address shown in the panel.

Provider presets: Gmail uses smtp.gmail.com, port 587, STARTTLS. Outlook/Microsoft 365 uses smtp.office365.com, port 587, STARTTLS. Yahoo uses smtp.mail.yahoo.com, port 465, TLS/SSL.

Authentication failures: Successfully signing in to webmail does not prove that SMTP access is enabled. Verify the server and port, use an app password when required, and confirm that the provider permits authenticated SMTP for the account.

A personal Pushover email gateway address can be used as a destination when email-to-Pushover delivery is desired. For native RigPi push alerts, use the separate Pushover Notifications configuration instead.

Security: SMTP credentials are sensitive and are stored locally on the RigPi. Use a dedicated app or mailbox password when possible. Disconnect removes the saved SMTP configuration. After Factory Reset, configure outgoing email again.
