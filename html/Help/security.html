Security

RigPi controls station equipment and can transmit when an account has permission. Treat it like any other Internet-connected station controller: use strong account passwords, expose only the connection you need, install operating-system updates, and remove access that is no longer required.

Never expose an unencrypted RigPi address to the Internet. Remote browsers should connect through a configured https:// DuckDNS or Cloudflare address (described below). Do not forward the RigPi web, SDR, SSH, database, VNC, or other service ports directly unless you understand and accept the risk.

Local and remote connections

A local address such as http://rigpi5.local can be used on a trusted home or station network. Secure remote operation requires HTTPS. In addition to encrypting browser traffic, HTTPS provides the secure browser context required for remote microphone access and other browser features.
 

RigPi provides two HTTPS choices. Configure them under SETTINGS > Accounts > User Settings. Complete setup instructions are in External Accounts.

Native HTTPS with DuckDNS (free)

Free permanent hostname; automatically renewed Let’s Encrypt certificate; direct connection to the station.

Requires a reachable public IP address and router forwarding of TCP port 443. DuckDNS publishes the station’s public IP address. It generally does not work through carrier-grade NAT (CGNAT), double NAT, or blocked inbound ports without additional network changes.

Cloudflare Tunnel (free plus your own domain)

No router port forwarding; works through CGNAT and most restricted Internet connections; does not publish the station’s origin IP address.

Uses a third-party tunnel service. A permanent named station address requires a domain owned by the station operator.

Use the complete secure address. A remote address begins with https://, not http://. Test it from outside the station network, such as a phone with Wi-Fi disabled. Some routers cannot use the public address from inside the same LAN.

Native HTTPS with DuckDNS

RigPi obtains and renews the certificate and keeps the DuckDNS address synchronized with the station’s public IP address. Forward only external TCP port 443 to port 443 at the RigPi’s reserved local IP address. Do not forward port 80 or the individual SDR ports.
 

Secure same-origin paths such as https://your-name.duckdns.org provide remote SDR access through the main RigPi HTTPS connection. There is no need to expose ports except for port 443.
 

•Before enabling the forwarding rule, replace all factory or weak RigPi passwords.

•Disable or move the router’s Internet administration page if it uses external port 443.

•If the DuckDNS name resolves but the connection times out, compare the router’s WAN address with the public address shown by DuckDNS. A mismatch can indicate stale DNS, double NAT, or CGNAT.

•The DuckDNS token is stored locally in a root-only file and is not returned to the browser.

DuckDNS is naming and certificate support, not a privacy proxy. Anyone resolving the hostname can see the station’s public IP address. Choose Cloudflare Tunnel to conceal the origin address or to avoid inbound port forwarding.

Cloudflare Tunnel

Cloudflare Tunnel makes an outbound connection from RigPi to Cloudflare, so the router does not accept a new inbound connection and no port-forwarding rule is required. This is normally the better choice for CGNAT, double NAT, ISP-blocked inbound ports, or origin-IP concealment.
 

Protect the Cloudflare account with a strong unique password and multi-factor authentication. Treat the tunnel token as a password: do not paste it into messages, screenshots, or support requests. Remove unused tunnels and DNS records from the Cloudflare dashboard.

Accounts and station permissions

•Give every guest user a separate RigPi account and a strong, unique password.

•Reserve administrator access for people who must change system-wide settings.

•Grant radio control and transmit permission only when required. Use a receive-only or restricted access level for observers.

•Delete unused accounts promptly and review account requests before approval.

•Do not share browser sessions. Sign out when using a shared or public computer.

Browser audio, SDR, and site permissions

Microphone permission is stored separately for each browser, device, and RigPi address. Permission granted to a local address does not automatically apply to its DuckDNS or Cloudflare address. Grant camera, microphone, clipboard, and notification permission only to the expected RigPi hostname.

Temporary Remote Support

Temporary Remote Support provides time-limited, key-only diagnostic access for a trusted technician. It can use a temporary encrypted address that requires no domain or router change, or an existing secure station address.
 

•Verify the technician’s complete Ed25519 public key and fingerprint through a trusted channel.

•Choose the shortest practical access period and remain available during the session.

•Send only the displayed Support URL. Never send a private key, password, DuckDNS token, Cloudflare token, or API credential.

•Select Revoke Now when the session is complete. Access also expires automatically and is cleared by a restart.

Support access is powerful. An authorized technician can inspect and change the operating system. Enable it only for someone you trust.

Firewall, intrusion protection, and updates

RigPi includes the UFW firewall and Fail2ban as defense-in-depth measures. A firewall reduces unnecessary network exposure, and Fail2ban can temporarily block repeated failed login attempts. Neither replaces HTTPS, strong passwords, safe router configuration, or timely updates. See the UFW topic before changing firewall rules.
 

Install Raspberry Pi OS and RigPi security updates promptly. Review unexpected login notifications and access logs. Avoid installing unneeded Internet-facing software, and remove services that are no longer used.

Passwords, tokens, and backups
 

•Use a password manager and never reuse the administrator password on another service.

•Treat DuckDNS, Cloudflare, Elmer, SMTP, callbook, notification, VPN, and API credentials as sensitive.

•Keep downloaded RigPi backups private. They can contain station records and account settings.

•Do not include passwords, tokens, private keys, or personal information in screenshots or support messages.

Factory Reset rebuilds the station database and removes managed DuckDNS, Cloudflare, Elmer, Remote Support, WireGuard, ZeroTier, browser, and other private station data. It also removes release-development backups managed by RigPi.
 
Factory Reset does not delete the external DuckDNS hostname, Cloudflare tunnel, or DNS records from those providers’ accounts, and it intentionally preserves unrelated personal SSH keys. Remove those external records and keys separately before transferring a system.

Remote-access checklist
 

1.Set strong, unique passwords and confirm each user’s permissions.

2.Choose one HTTPS method: DuckDNS for a direct connection with reachable port 443, or Cloudflare Tunnel when port forwarding or public-IP exposure is undesirable.

3.Use the secure same-origin SDR path, normally /sdr1 for the first account. The sdr1 option is entered in SETTINGS > Accounts > Account Editor.

4.Test from outside the station LAN and confirm the browser shows the expected HTTPS hostname.

5.Verify receive audio, microphone permission, radio control, and PTT into a dummy load.

6.Review accounts, tunnel settings, router rules, updates, and logs periodically.
