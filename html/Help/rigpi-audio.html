RigPi Audio

Current RigPi receive and transmit audio runs directly between RigPi and a modern web browser. The same Audio panel is available in the full ELMER SDR window and when SDR is embedded in the Tuner or Keyer window. No Mumble or Plumble client is required.

Begin with low volume. Turn down headphones, speakers, and the RigPi Level control before starting audio. Begin around 10–20% and increase it gradually. Use a headset when testing transmit audio to prevent feedback.

Understand the three audio paths

Purpose

Audio path

Hardware or selection

Listen to SDR

SDR demodulator → RigPi → browser → headset or speakers

Select RX Audio: SDR. No radio sound device is required.

Listen to the radio

Radio receiver audio → radio USB CODEC → RigPi → browser

Select RX Audio: Radio and the radio's receive-audio input.

Transmit voice*

Browser microphone → RigPi → radio USB CODEC → transmitter

Select the browser microphone and TX Output (Radio CODEC). Configure the radio to use USB/data transmit audio.

Run digital modes

SDR audio → ALSA Loopback → WSJT-X, Fldigi, or another program on RigPi

Use the digital-program audio configuration; browser listening is optional.

*Transmit audio is only available through a secure (https) connection.  This is a browser requirement.  However you can test the microphone by opening the Chromium browser on the Raspberry Pi desktop and connecting with http://localhost.  Localhost (or 127.0.0.1) is a special case where browsers can access the mocrophone.  Remote connections or external browsers still require a secure connection.  Running a browser on the Raspberry Pi Desktop is not recommended because of the increased CPU load a browser demands.  You can connect a microphone to RigPi through a USB connection.
 
CAT is not audio. CAT control can change frequency and mode without carrying receive or transmit sound. Many modern radios expose both a CAT serial port and an audio CODEC through one USB cable, but they remain separate functions and must both be configured
 

Choose the station audio hardware

For most current radios, the radio's built-in USB audio CODEC is the preferred bidirectional audio connection. If the radio does not provide USB audio, use a supported external USB sound interface connected to the radio's accessory, data, or audio jacks.

•Radio USB CODEC: usually the simplest choice. One USB cable may provide both CAT and audio.

•External USB audio interface: use this when the radio has no built-in CODEC. Follow the radio's requirements for isolation, levels, PTT, and accessory-port wiring.

•SDR hardware: provides receive spectrum and digitally demodulated receive audio; it normally does not provide the radio's transmit-audio input.

•Original MFJ RigPi Audio board: legacy hardware. It is not necessary for normal RigPi 5 SDR browser audio. See RigPi Audio Update only when maintaining an earlier RigPi Audio-board installation.

Receive audio: quick setup

1.Open ELMER SDR, the Tuner, or the Keyer, then open the SDR side panel and select Audio.

2.Choose RX Audio: SDR to hear the SDR demodulator. Confirm that the SDR is connected and tune a visible signal.

3.To hear the transceiver instead, choose RX Audio: Radio, then select the correct radio input from the adjacent device list.

4.Turn down the listening device and set Level low.

5.Select C to send the audio equally to both ears.

6.Click Start Audio. Browsers require this user action before a page may play sound.

7.Confirm that the audio indicator turns green and the receive VU meter responds. Increase Level gradually.

The RX Audio selection changes only what this user hears. It does not change the spectrum, waterfall, tuning, PTT, or transmit-audio device. The selection is retained for the signed-in RigPi account.

Audio panel controls

Control

Function

Start/Stop Audio

Starts or stops the browser audio stream.

RX Audio

Selects audio demodulated by the SDR or receive audio supplied by the radio CODEC.

Radio input

Selects the ALSA capture device used when RX Audio is set to Radio.

Level

Controls this browser's listening level. Start low, particularly with headphones.

L / C / R

Pans the stream left, center, or right. To monitor two devices—or one device at two frequencies—select L for one stream and R for the other. Select C for normal listening in both ears.

VU / SCOPE / FFT

Changes the audio display only; it does not change the sound.

TX Output (Radio CODEC)

Selects the RigPi audio playback device that feeds transmit audio to the radio.

TX Level and TX VU

Sets browser-microphone drive to the radio and displays its level. Avoid the red clipping indication.

Transmit audio: setup and safe test

1.Connect the radio's USB audio CODEC or a supported external USB audio interface to RigPi.

2.In the Audio panel, select the radio device under TX Output (Radio CODEC). Do not select the Raspberry Pi speaker output or an SDR receive-only device.

3.Select the desired microphone in the browser audio controls. If prompted, allow microphone access for the RigPi site.

4.Configure the radio so that the selected operating mode uses its USB, data, or accessory audio input rather than the front-panel microphone. The exact menu name is radio-dependent.

5.Set TX Level low. Connect a dummy load or select minimum safe power for the first test.

6.Test PTT independently. PTT and transmit audio are separate paths: a radio can key successfully while receiving no modulation.

7.While speaking normally, increase TX Level until the TX VU responds without frequent red clipping. Then check the radio's ALC or input meter and adjust its USB/data input level as necessary.

8.Release PTT and verify immediately that the radio returned to receive.

Transmit safety: Selecting an audio device does not authorize transmission. Confirm the frequency, mode, antenna or dummy load, power, and radio input selection before pressing PTT. Stop immediately if the radio remains keyed, the TX audio clips, or the radio shows excessive drive.

Browser and remote-access requirements

•Use a current browser. Google Chrome is recommended when microphone behavior is inconsistent.

•Remote microphone capture requires a secure https:// RigPi address. Native DuckDNS HTTPS and Cloudflare remote access both provide HTTPS. Browser handling of a local address can vary.

•Microphone permission is stored separately for each browser, device, and RigPi address. Permission granted to rigpi5.local does not automatically apply to a DuckDNS or Cloudflare address.

•Check the browser's site controls if the wrong microphone is selected or permission was denied.

•On phones and tablets, silent mode, Bluetooth routing, and the physical volume controls can affect playback even when the RigPi VU meter is moving.

Chrome local-LAN microphone override: HTTPS is preferred. If Chrome blocks microphone access to a trusted local RigPi address, open chrome://flags/#unsafely-treat-insecure-origin-as-secure. Enable Insecure origins treated as secure, enter the complete RigPi origin—normally http://rigpi5.local—and relaunch Chrome. If an explicit port is used, include it, for example http://rigpi5.local:8001. Reopen RigPi and allow microphone access when prompted. Add only a RigPi you trust on your local network. This override does not encrypt the connection and must not replace HTTPS for remote access.

Troubleshooting

Symptom

What to check

No sound and no receive VU movement

Click Start Audio. For SDR audio, confirm the SDR is connected, tune a visible signal, and select the correct mode and bandwidth. For Radio audio, select the correct receive CODEC. Reload the page if the audio indicator does not turn green.

VU moves but nothing is heard

Raise Level gradually, select C, check the device volume, unmute the RigPi browser tab and site, and disconnect an unintended Bluetooth output.

Only FM audio works

Confirm which path is being heard. An SDR can demodulate FM while the radio CODEC or sideband mode remains misconfigured. Check RX Audio selection, mode, bandwidth, radio CODEC, and the radio's USB/data audio menus.

Audio is choppy or delayed

Use a wired network when practical, close duplicate RigPi tabs, reduce demanding SDR features, and check Raspberry Pi load and temperature. Raspberry Pi 5 is strongly recommended.

Microphone is unavailable

Use HTTPS, allow microphone permission for this RigPi address, select the correct browser input, and reload the page. For a trusted local HTTP address in Chrome, use the documented Insecure origins treated as secure override.

Radio keys but has no modulation

Select the correct TX Output CODEC, verify browser microphone permission, and configure the radio to use USB/data audio. Then raise TX Level gradually.

Transmit audio is distorted

Reduce TX Level and the radio's USB/data input gain. Avoid red TX VU clipping and excessive radio ALC.

Echo or feedback

Use a headset, close duplicate audio sessions, move speakers away from the microphone, and stop receive audio temporarily while testing transmit.

Wrong account or radio audio

Confirm the signed-in account, selected SDR instance, RX radio input, and TX CODEC. Shared radios do not require every user to share the same browser audio preferences.

Diagnose one stage at a time: visible signal → receive VU → browser sound → microphone permission → TX VU → radio CODEC → PTT → on-air modulation. This finds the failed stage without changing several unrelated settings.
